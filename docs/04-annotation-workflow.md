# 图像标注与复核

本文覆盖从导入图片到“可进入数据集”的完整人工/半自动标注流程。核心原则只有一句：**保存标注 ≠ 确认复核**。

---

## 1. 导入图片

WPF 标注页的“项目 → 导入”，或后端 `images.import`：

- 支持文件或目录（目录会递归查找支持的扩展名）；
- 校验图片可被 Pillow 打开，并计算来源 SHA256；
- 同来源文件重复导入会被识别为重复，不重复复制；
- 来源文件变化后再次导入会报错，要求使用新文件名；
- 自动从候选目录探测同名 YOLO 标签：
  `../Main_labels`、`<父目录>_labels`、`<同目录>/labels`、`<同目录>`；
- 标签类别按**名称**对齐到项目类别表，新类名追加到末尾；
- 目标 stem 冲突时追加哈希后缀，绝不覆盖；
- 新导入的样本统一进入新批次 `images_<时间戳>_<随机串>`，状态为 `pending`。

导入后必须逐张确认，才能进入数据集。

## 2. 绘框与编辑

### 2.1 鼠标与键盘

| 操作 | 行为 |
| --- | --- |
| `W` | 进入绘框模式；拖拽创建矩形 |
| `Esc` | 回到选择模式 |
| 拖动控制点 | 调整框大小（八个方向） |
| `R` | 恢复适配视图（fit） |
| 滚轮 | 以鼠标位置为中心缩放 |
| 中键拖动 / 空格拖动 | 平移画布 |
| 方向键 | 微调选中框 |
| `Delete` | 删除选中框/顶点 |
| `Ctrl+C` / `Ctrl+V` | 复制/粘贴 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销/重做（最多 100 步） |
| `A` / `D`（按住） | 连续上一张/下一张，松开停止 |
| `F` | 保存并确认当前图片，进入下一张 |
| `P` | 绘制多边形；双击完成 |
| 双击边 | 在轮廓上插入顶点 |

### 2.2 坐标与几何

- 内存与 UI 使用 `[0,1]` 归一化坐标；
- 持久化到 `.annotation.json` 时乘以原图宽高，保存为像素坐标；
- `Box.SetBounds()` 会把框限制在 `[0,1]` 和对象 ROI 内；
- 多边形、孔洞、原始轮廓分别存储在 `polygons`、`holes`、`raw_polygons`；
- 编辑框会清除 `raw_polygons` 并把来源改为“人工”；
- 每个对象有稳定的 `object_id`；视频跟踪另有 `target_id`（终身目标 ID，-1 表示非跟踪对象）。

### 2.3 撤销与保存

- WPF `AnnotationHistory` 保存最近 100 个状态，新编辑会清空 redo；
- 保存成功后才切换图片；保存失败时保留编辑，可重试；
- 若服务端 revision 已变化（例如另一个窗口修改过），会提示冲突，**不覆盖**已有数据；
- 原样保存不会增加 `geometry_revision`，因此不会撤销已有复核状态。

## 3. SAM 辅助分割

交互式 SAM 由桥接进程内的 `InteractiveSam` 持有，同一个模型/图片只加载一次，换图或换模型时释放缓存。

### 3.1 提示类型

- **前景点**（`Q`）：`labels=1`；
- **背景点**（`E`）：`labels=0`；
- **框提示**：`bbox`，与点提示可组合；
- **ROI**：限定分割区域，必须是原图范围内的有效矩形；
- **新目标**：开始下一组提示；
- **清除本次分割**：恢复到本次提示开始前的轮廓。

至少需要一个正点或一个框，否则拒绝推理。没有有效 mask 时保留最近一次结果并提示错误，不会写入空对象。

### 3.2 结果写回

`mask_box()` 会把 mask 转成：

- 外轮廓 `polygons`（默认做轮廓简化，`epsilon` 可调）；
- 原始轮廓 `raw_polygons`；
- 孔洞 `holes`；
- 紧致外接框 `x1/y1/x2/y2`；
- 来源 `AI`。

简化后的外轮廓如果切进了未改变的孔洞，会自动回退到原始外轮廓，避免拓扑被破坏。

### 3.3 轮廓简化

`annotation.simplify` 使用 `epsilon`（像素误差）对 `raw_polygons` 做简化；若结果少于 3 个点则保留原轮廓。该操作只改前端返回的对象，仍需显式保存。

## 4. 复核（Review）

复核台账位于 `Config/review.json`，详见 [项目目录与数据格式](./03-project-layout-and-formats.md)。

### 4.1 确认

`review.confirm` 会：

1. 校验图片可以打开（`Image.verify()`）；
2. 要求同名 `.txt` 存在（空文件表示“确认无目标”）；
3. 校验所有类别 ID 在类别表范围内；
4. 记录 `image_sha256`、`label_sha256`、`geometry_sha256`、时间、复核人。

任何一项不满足都会拒绝整批确认，不会出现“一半确认”的状态。

### 4.2 拒绝

`review.reject` 记录 `status=rejected` 和原因。被拒绝样本不会进入数据集；修正后可重新确认。

### 4.3 状态回退

以下变化会让 `confirmed` 自动退回 `pending`：

- 图片文件内容变化；
- `.txt` 内容变化；
- 几何指纹（`.txt/.mark/.segments.json/.annotation.json` 的组合哈希）变化。

因此，“改了一个框但没重新确认”不会被误当成已复核数据。

### 4.4 F 键的语义

`F` 执行“保存 + 确认 + 下一张”。它只在画布获得焦点时生效，避免在输入框中误触；长按不会连续确认。

## 5. 分割数据集导出

当目标是实例分割（而不是检测框）时，使用 `segment_dataset` 任务（WPF：训练/数据集页的“分割数据集”入口）。

导出前会逐张检查：

- 只包含 `confirmed` 样本；
- 每个对象必须有真实 `polygons`，只有检测框会被拒绝；
- 含孔洞时必须显式选择“填孔”；
- 多连通区域必须显式选择“拆分实例”；
- 类别 ID 必须有效；
- 轮廓顶点必须是有限数且在 `[0,1]`；
- 轮廓面积不能为零；
- 轮廓不能超出 ROI。

问题会汇总为 `issues` 返回，**一张不合格就整批不导出**。空图片必须已明确保存空标注并确认，否则会被视为“没有已复核图片”。

输出结构与检测数据集类似：

```text
segmentation_dataset/versions/<version>/
├── images/train|val/
├── labels/train|val/
├── classes.txt
├── dataset.yaml
└── dataset_manifest.json
```

分组划分同样按视频/批次分组，验证集不会混入同组近邻帧。

> 检测数据集与分割数据集是两条独立出口；发布门禁会检查基准集标签是否混用检测框与多边形。

## 6. 常见误区

| 误区 | 实际行为 |
| --- | --- |
| “点了保存就算完成” | 保存只写文件；必须确认复核才进数据集 |
| “空图片不用管” | 空图片也要保存空 `.txt` 并确认，才会作为负样本 |
| “改完框复核状态还在” | 几何变化会让状态退回 `pending` |
| “SAM 结果自动保存” | SAM 只返回候选对象，仍需用户接受并保存 |
| “有检测框就能导出分割” | 分割导出要求真实多边形轮廓 |
| “失败一张没关系” | 分割导出是整批原子操作，有问题就整体拒绝 |
